## Commands

```bash
docker compose up -d  # MongoDB (single-node replica set), Redis, MinIO (S3) for local dev
npm run dev         # tsx watch src/index.ts (needs the services above and a .env copied from .env.example)
npm run build       # tsc → dist/
npm start           # node dist/index.js
npm run typecheck   # tsc on src/ and tests/
npm run lint        # ESLint (typescript-eslint, type-aware async rules)
npm run format      # prettier (single quotes, trailing commas, printWidth 110); format:check in CI
npm test            # vitest run — all tests (no Docker needed)
npm test -- tests/unit/i18n.test.ts     # one file
npm test -- -t "replays the stored"     # tests matching a name
npm run test:watch
npm run openapi     # regenerate docs/openapi.json (needs .env, no DB)
npm run docs:inventory   # regenerate docs/DATA_INVENTORY.docx from docs/DATA_INVENTORY.md
npm run test:load   # load test: 1,000 providers, real app over HTTP, fails if read p95 ≥ 300 ms (LOAD_* env vars)
npm run seed:staging -- --providers 200   # demo data for staging (refuses production)
UPDATE_API_COVERAGE=1 npm test -- api-coverage   # regenerate docs/API_COVERAGE.md after adding endpoints
```

- CI (`.github/workflows/ci.yml`) runs typecheck, lint, format:check, test and build — keep all five green.
- Tests live in `tests/` (`unit/`, `integration/`), not next to the code. `tests/setup/global-setup.ts` starts one in-memory MongoDB **replica set** for the run; `tests/setup/env.ts` sets env vars and swaps `ioredis` for `ioredis-mock`. In a DB test file, call `useTestDatabase()` (own database per file, collections + Redis wiped after each test). `createTestApp()` gives the full Express app for supertest; `signTestToken({ id, role })` gives a bearer token. The first run downloads a `mongod` binary.
- **Known local issue (Windows, Node 24.15):** a test run sometimes dies with no output and exit code `-1073740791` (`0xC0000409`, a native fail-fast). It's not a failing test — every run that survives passes everything. It reproduces in a plain Node script that just connects to the in-memory MongoDB, runs a transaction and disconnects in a loop. Ruled out: test logging, Sentry, compression, worker isolation, file parallelism, and hosting mongod in a separate process. Just re-run; don't chase it as a test failure. **It's specific to Node 24:** 10 alternating full-suite runs on each version gave 3/10 crashes on Node 24.15 and 0/10 on Node 22.23 LTS, which is also what CI uses. Run tests locally on Node 22 to avoid it (`.nvmrc` pins `22`; `nvm use`).
- Environments: `NODE_ENV` = development | test | staging | production. `env.isDeployed` (staging + production) = JSON logs to stdout only, no stack traces in error responses; `env.isProduction` alone gates the SMS log driver, `/docs` and the staging seed. Deployment: `Dockerfile`, `deploy/` (compose + Caddy + env template), `.github/workflows/deploy.yml`, `docs/DEPLOYMENT.md`.
- Env vars are validated on import of `src/config/env.config.ts`; missing `MONGO_URI` / `JWT_SECRET` / `FIELD_ENCRYPTION_KEY` crashes at boot. Read env only through the `env` object there.
- In dev, OTP codes are printed in the server log (`[SMS → +2010…]`); tests read them with `lastSmsCode(phone)` from `tests/helpers/fixtures.ts` (also `signUp(app, role)`, `loginWithOtp`, `createUserWithToken(role)`).
- MongoDB must run as a replica set (transactions are used for booking/offer races); `MONGO_URI` uses `?directConnection=true` against the compose container.
- Health checks: `GET /api/v1/health` (liveness), `/health/ready` (Mongo + Redis, 503 when down), `/health/jobs` (503 when a scheduled job stopped — each maintenance job records a heartbeat via `runMaintenanceJob`). Runbook: `docs/OPERATIONS.md`; security review: `docs/SECURITY.md`. API docs (outside production): Swagger UI at `/docs`, spec at `/docs/openapi.json`. Bull Board: `/admin/queues` (basic auth; only mounted when `BULL_BOARD_PASSWORD` is set).
- Every request gets an `X-Request-Id` (kept from the caller if sane); it's echoed in the response and added to every log line written for that request (`getRequestId()` from `src/utils/request-context.ts`). Logs are JSON in production. Unexpected errors go to Sentry when `SENTRY_DSN` is set; `src/instrument.ts` turns off all of Sentry's automatic data collection (bodies, headers, local variables…) because of medical data — keep it that way and attach only non-sensitive context explicitly.

## Architecture

Express + TypeScript (CommonJS, decorators enabled) + Mongoose + Socket.IO + BullMQ + TypeDI. Layering: **controller → use-case / service → Mongoose model**. There is no repository layer.

### Boot sequence (`src/index.ts`)
`reflect-metadata` must be the first import (TypeDI). Then: `new Server(getGlobalControllers())` → `initDatabase()` (connect + seeds) → `PresenceCleanup.cleanStalePresence()` → `runServer()` (Socket.IO, `initQueues()`, listen) → `setupScheduledTasks()`. SIGINT/SIGTERM closes sockets/HTTP, cleans presence, `shutdownQueues()`, disconnects DB. Anything new that holds connections must be wired into both startup and this shutdown path.

### HTTP layer
- Controllers implement `IBaseController` (`path`, `router`, `initializeRoutes()` called in the constructor) and **must be added to `controllerClasses` in `src/api/controllers/index.ts`** to be mounted under `API_PREFIX` (default `/api/v1`). Non-controller routers (uploads, webhooks) go in `standaloneRouters` in `src/api/routers/index.ts`.
- Per-route middleware order: `CheckAppStatusMiddleware → r.validate → ...Auth(UserRole.X, …) → this.handler.bind(this)`. `Auth(...roles)` (`src/api/middlewares/auth`) = access token check → account still active (DB lookup each request: suspended → 403 `ACCOUNT_SUSPENDED`, deleted → 401) → role check (omit roles for "any signed-in user"). `AdminGuard` = `Auth(UserRole.ADMIN)` + `AdminPermissionMiddleware` (admin sub-role, below). Roles live in `src/interfaces/enums.ts`; one role per account (spec §2).
- **Every route is declared with `defineRoute()`** (`src/docs/openapi.ts`): method, path, summary, tags, `auth`, `idempotent`, zod `request: { params, query, body }` and `response: { schema, status, paginated }`. It registers the route in the OpenAPI spec and returns `{ path, validate }`; mount with `this.router.get(r.path, CheckAppStatusMiddleware, r.validate, …)`. Docs and validation come from the same schemas, so they can't drift. See `user.controller.ts`.
- Schemas live in `src/api/validations/<domain>/<domain>.validation.ts`. Import `z` (and `objectId`, `paginationQuery`) from `src/api/validations/zod.ts`, never from `'zod'` directly — that instance has `.openapi()` and translation-key default messages (`validation.required` / `validation.invalid_value`; override per field with `{ error: 'validation.<key>' }`). Validation failure → `422 VALIDATION_ERROR` with `fields: { input: [messages] }`; on success `req.params/query/body` hold the parsed values.
- Handlers wrap logic in `try/catch` and `next(err)` — Express 4 does **not** forward errors thrown from async handlers. Respond via `HttpResponse.ok / created / accepted / paginated / noContent`. Success envelope is `{ data, meta? }` (spec §7.0). For lists, use `parsePagination(req.query)` (`?page=&per_page=`, max 100) from `src/utils/response/pagination.ts` and pass the result to the service and to `HttpResponse.paginated` → `meta: { page, per_page, total, last_page }`.
- Errors: throw typed classes from `src/utils/types-errors` (extend `HttpError(status, code, { messageKey?, params?, fields? })`); `GlobalErrorHandlerMiddleware` renders `{ error: { code, message, fields? } }`. Every error carries an `ErrorCode` (`error-codes.ts`, mirrors spec §7.0) — clients branch on the code, so for a spec error use its domain class (`OfferTakenError`, `SlotUnavailableError`, …) rather than a generic one. Generic errors take an optional key for a more specific message: `new NotFoundError('errors.user_not_found')`.
- **Security tests guard every route** (`tests/integration/security.test.ts`): a route without `...Auth()` must be added to `PUBLIC_ROUTES` there (deliberately), new sensitive fields go in its `ENCRYPTED` list, and no field/param may look like a location. `api-coverage.test.ts` fails when a spec endpoint is neither implemented nor mapped to a later milestone in its `DEFERRED` list.
- Rate limits: `RateLimiterMiddleware` (global, per IP, Redis, fails open) and `AuthRateLimiterMiddleware` on public auth routes; for a paid or abusable action use `isOverLimit()` directly and fail closed (OTP, uploads).
- Routes the spec marks with `Idempotency-Key` (`POST /bookings`, `/payments/initiate`, `/packages/{id}/subscribe`) add `IdempotencyMiddleware` **after** `IsAuthenticatedMiddleware` (keys are scoped per user + route; Redis-backed, fails closed).
- `req.user` is augmented in `src/types/express/index.d.ts`.
- **API JSON is snake_case** (spec §7), models are camelCase. Presenters in `src/api/presenters/<domain>.presenter.ts` map rows/documents to the response shapes (`id` string, never `_id`; ISO dates). Public responses carry one localized `name` (`localized(nameAr, nameEn, lang)` — Arabic unless `en` is requested and filled); admin responses carry both `name_ar` / `name_en`. Request bodies go the other way with `camelizeKeys(req.body)`.
- Public lookups add `PublicCacheMiddleware()` (`Cache-Control: public` + `Vary: Accept-Language`). Admin routes use `...AdminGuard` after the validator. **Admin sub-roles (M3.5)**: `user.adminRole` (`super_admin | verifier | support | finance | marketing`; null on an admin = super_admin), read from the DB on every request. Who may call which admin route is the one table `ADMIN_RULES` in `middlewares/auth/admin-permissions.ts` (route pattern as registered + method); a new admin route is super_admin only until you add a rule — `tests/unit/admin-permissions.test.ts` snapshots the whole table, so review the diff. Health text (booking notes, dispute descriptions) only for `canReadHealthText` roles; other roles get it as null, unaudited.
- Duplicate-key errors from unique indexes become `409 CONFLICT` (`errors.duplicate`) in the error handler — no need to pre-check uniqueness.

### i18n
- Launch is Arabic only, but no user-facing text is hard-coded: it lives in `src/locales/ar.json` (source of truth) and `en.json` (empty until English launches; missing keys fall back to Arabic). Use `t(key, params?, lang?)` from `src/utils/i18n` (`{{name}}` placeholders).
- Errors hold a translation key and are translated only in the error handler, using `resolveLanguage(req)`: `Accept-Language` → `req.user.language` → `ar`.
- `TranslationKey` is generated from `ar.json`, so a wrong key is a compile error, and so is a new `ErrorCode` without an `errors.<CODE>` entry. Keys under `errors.` are `UPPER_CASE` for error-code defaults and `lower_snake` for specific messages.

### Services
`src/services/<domain>/`: a `<name>.service.ts` plus one `<action>.usecase.ts` per operation (class with `execute()`), all `@Service()` classes, re-exported from `index.ts`.
- Get dependencies with `Container.get(X)` (in controllers and as service fields: `private readonly audit = Container.get(AuditService)`). **Don't use TypeDI constructor injection**: `npm run dev` runs on tsx/esbuild, which doesn't emit decorator metadata, so constructor params resolve to the wrong thing in dev while working in the `tsc` build.

Cross-cutting services (Phase 0, M0.3):
- **Settings** (`services/settings`): `SettingsService.get('fallback_window_minutes')` for any spec-configurable value — never hard-code those numbers. Defaults + per-key validators live in `settings.definitions.ts`; Mongo stores only admin overrides; cached in Redis and dropped on `update()`, which also writes the audit entry.
- **Audit** (`services/audit`): `AuditService.log(auditContextFrom(req), { action: '<entity>.<verb>', entityType, entityId, metadata })` for every admin write and every medical-data read. Awaited — if it can't be written the action fails. `audit_logs` is append-only (update hooks throw).
- **Storage** (`services/storage`): private S3-compatible bucket. Uploads land under `tmp/<ownerId>/<purpose>/`; attach endpoints call `promote()` (checks owner + purpose), clients only get `signedUrl()` (10 min). Store keys, never URLs.
- **Cache** (`src/utils/cache/cache.ts`): `cached(namespace, key, ttl, load)` for read-mostly data; every write path must call `invalidateCacheNamespace(namespace)` (the admin services do it in `afterWrite`). Direct DB edits bypass this and stay stale until the TTL. Cache plain JSON rows (both languages), not documents.
- Admin services follow one shape: load the doc, `applyPatch(doc, patch)` (returns only real changes), `save()`, then audit `{ changes }` + invalidate cache — see `location-admin.service.ts`.

Domain services so far:
- **Auth** (`services/auth`, spec §7.1): phone + OTP only, no passwords. `OtpService` (4-digit codes, HMAC-hashed, 2-min expiry, 5 attempts counted atomically, Redis limits: 1/min + 3/10 min per phone, 10/hour per IP); phones must match `EGYPT_MOBILE` (anti SMS-pumping). `TokenService`: access JWT (`typ: 'access'`, 1 h) + opaque refresh token stored as a SHA-256 hash, rotated on every use; reusing a spent refresh token revokes its whole session (`familyId`). New numbers get a 15-min registration JWT (`typ: 'registration'`) for `/auth/register`, which creates the user + role profile in one transaction. JWT helpers in `services/auth/jwt.ts` (HS256 pinned). SMS goes through `SmsService` (`SMS_DRIVER=log` in dev; it throws in production). Admins are created with `npm run admin:create -- --phone … --name …`, never via sign-up.
- **Users** (`services/user`): `UserService.getMe` (returns `{ user, providerProfile, avatarUrl }` — pass it whole to `presentMe`), `setAvatar`, `UpdateMeUseCase`, `DeleteAccountUseCase` (soft-deletes, revokes sessions, frees the phone), `DeviceService` (FCM tokens move to whoever logs in on the device).
- **Addresses** (`services/address`): text only, must be in a bookable area of the given governorate; exactly one default (unique partial index + transaction in `setDefault`). Request bodies are `z.strictObject`, so stray fields (coordinates!) get 422 `validation.unknown_field` by name. Presenter builds `full_text` from `address.*` translation templates.
- **Patient & medical** (`services/patient`): always load the profile with `PatientProfileService.getOwned(userId, id)` first — another user's profile is a 404. Conditions/medications/allergies share one generic `MedicalRecords` class (`MedicalRecordService.conditions` etc.). Medical text uses `encryptedString`, so read these models without `.lean()` and convert with `toObject()` (runs the decrypting getters). Every medical read/write calls `auditMedical(...)` — metadata names the section/fields, **never** the values (the audit log isn't encrypted).
- **Uploads**: `UploadMiddleware(field, allowedMimes)` after `...Auth()` — memory, 10 MB, type detected from the file's bytes (`utils/file-type.ts`), 60/hour/user; then `r.validate` for the text fields. Document multipart routes with `defineRoute({ upload: { field: 'file' }, request: { body } })`. Two-step flow: `POST /uploads` → `tmp/<user>/<purpose>/…`, then the attach endpoint calls `StorageService.promote()` (same user + purpose only). Tests fake S3 with `useFakeStorage()` + `fakeBucket` and real-format bytes from `sampleFiles` (`tests/helpers/storage.ts`).
- **Providers** (`services/provider`, spec §7.10): `ProviderProfileService.getOwn(userId)` loads the caller's profile (hydrated — license/syndicate numbers are encrypted, so no `.lean()` when you need them). Service areas, services+prices and weekly availability are **embedded arrays** on the profile (`serviceAreas`, `services`, `availability`; times are Africa/Cairo "HH:mm"); time off is its own collection. `ProviderCoverageService` replaces each list wholesale and reports every bad entry as `areas.<i>.<field>` etc. Identity fields (`type`, license, syndicate) are editable only in `EDITABLE_STATUSES` (draft / changes_requested / rejected). `checklist()` drives both the onboarding block and `submit`. `PROVIDER_STAFF` share the routes but can't PUT areas or services.
- **Verification** (`VerificationService`): provider `submit` → pending; admin `approve` / `requestChanges` / `reject` (pending only, each in `withTransaction` from `src/database/transaction.ts`, audited) and `reviewDocument`. Approval accepts still-pending documents and is refused while any is `not_matching`. Anything that changes provider prices, status or accepting must `invalidateCacheNamespace(PROVIDER_PRICES_CACHE)` — `CatalogService.startingPrices()` reads it.
- **Time**: all scheduling uses `src/utils/time/cairo.ts` (`cairoToUtc(date, 'HH:mm')`, `cairoDate()`, `dayOfWeek`, `addDays`). Egypt has DST (UTC+2 / +3), so never add a fixed offset. `cairoToUtc` is memoized (Intl formatting is ~20 µs a call and the slot engine calls it per slot) — it was the search hotspot in the M1.9 load test. Dates in the API are Cairo calendar dates ("YYYY-MM-DD"); instants are UTC ISO strings.
- **Bookings** (`services/booking`, spec §5–6): status changes go **only** through `transitionBooking()` (checks `booking-state.ts`, conditional update on the status you read → 409 on a race, appends `booking_status_history`, queues the event). Wrap booking work in `runBookingTransaction()` — events publish after commit. Anything that assigns or moves a provider's time must call `lockProviderSchedule(providerId, session)` then `assertProviderFree(...)` inside that transaction: the lock bumps `scheduleVersion` so concurrent transactions for one provider conflict and retry — that's the double-booking guard (mutation-tested). Pricing is the pure `computePrice` (commission on subtotal only; travel fee to the provider). Quotes are signed JWTs (`typ: 'quote'`, 10 min); `QuoteService.prepare()` is the single eligibility check, re-run at create/reschedule. Deadlines: `BookingDeadlineService.processDue()` every 30 s (maintenance queue) — direct timeout → fallback offers or expiry; broadcast timeout → expiry. Provider views hide patient/address/notes while pending; medical summary only via `hasMedicalAccess` (audited). Cash completion writes a `commission_due` ledger entry (`services/ledger`, append-only + atomic balance). Tests: `passDeadline()` pattern in `tests/integration/bookings.test.ts`.
- **Events** (`src/events/booking.events.ts`): `bookingEvents.publish/subscribe`; delivery channels subscribe (sockets: `emit/booking.emit.ts`; notifications: `services/notification/booking-notifications.ts` — both registered in `runServer`, so tests that need them call `registerBooking…()` themselves). Don't call sockets/push from booking code.
- **Notifications** (`services/notification`, spec §8): `NotificationService.notify(userIds, { type, template, params, data })` is the only way to notify — it writes the in-app record in each recipient's language (templates under `notifications.<template>.title/body` in `ar.json`; `params` may be a `(lang) => …` function for dates/names), emits `notification.new` on the user's socket room, and queues the FCM push unless the user turned that category off (`NOTIFICATION_SETTING_FOR`: reminders / promotions / chat — push only). The worker (`queues/workers/notification.worker.ts` → `sendPushToUser`) prunes dead tokens and throws only when nothing was delivered, so BullMQ retries. Without Firebase credentials pushes are skipped. Push `data` = ids + `type` + `notification_id`, all strings. Reminders: `BookingReminderService.processDue()` every minute, claim-once flags in `booking.remindersSent`. Sockets: `user:<id>` rooms automatically, `booking:<id>` via `booking:subscribe` (participants only, `canFollowBooking`). Tests: the push producer is mocked globally — assert with `queuedPushes()`; use `eventually()` for async listeners; booking scenarios via `createBookingWorld(app)` (`tests/helpers/booking-world.ts`).
- **Aftercare** (`services/aftercare`, spec §4.6, §6.8): `VisitReportService` (assigned provider, from `in_progress`; 24 h edit window; summary/vitals/procedures encrypted — vitals & procedures are JSON strings, read through `toView()`; patient reads audited via `auditMedical`). `ReviewService` (completed bookings only; rating recalculated immediately from visible reviews via `recalculate()` — call it whenever visibility changes; contact details auto-flag; public name via `reviewerName()`). `DisputeService` (window = setting `dispute_window_hours` after `completedAt ?? scheduledEnd`; opening moves the booking to `disputed`; resolve records refunds only — no money moves until Phase 2). Models in `database/models/aftercare/aftercare.models.ts`.
- **Moderation** (`services/moderation`): `AccountService.suspend / warn / activate / history` — suspending revokes sessions, stops a provider accepting, and cancels active bookings through `cancelActiveBookings()` (admin actor, so the other side is notified by booking events). Timed suspensions end via `liftExpired()` (5-minute maintenance job). `notify()` reaches suspended users too (only deleted ones are skipped).
- **Admin panel** (`services/admin`, controllers in `api/controllers/admin/`): dashboard/attention aggregates, bookings (force status through the state machine as `ADMIN`; `reassign` uses `lockProviderSchedule` + `assertProviderFree` like accept), users/providers/admin accounts, `AdminAnalyticsService.series` (`/admin/analytics`: Cairo day / week from Saturday / month buckets, zero-filled, aggregates only). `DocumentExpiryService.processDaily()` (06:00 Cairo) warns once per document (`expiryNoticeAt`) and pauses providers whose license expired until a newer one is approved as matching.
- **Discovery & slots** (`services/discovery`): `slot-engine.ts` is pure (`slotsForDay` = weekly hours − busy intervals; 30-min steps, ≥ 60 min lead, ≤ 60 days ahead) — unit-test rule changes there. **All busy time comes from `DiscoveryService.busyIntervals`**: time off today; bookings must be added there in M1.6 so search, slots and booking checks agree. `search()` is one aggregation (area + service + status + price → `$lookup` users for gender/active → sort → `$facet`); with a `date` it checks slots in memory over ≤ 500 candidates before paginating. Result rows project only card fields — keep encrypted identity fields out. Tests: `createBookableProvider({ areaIds, services })` in `tests/helpers/fixtures.ts`.
- **Locations** (`services/location`): `LocationService.activeGovernorates / activeAreasOf / searchAreas / findBookableArea` — "bookable" = active area in an active governorate; use `findBookableArea` wherever an address or booking takes an `area_id`. Area search matches Arabic spelling variants via `normalizeSearchText` (stored in `searchName`).
- **Doctors (M2.1)**: `ProviderType.DOCTOR` + `specialty` key from `services/catalog/specialties.ts` (append-only list; `presentSpecialty(key, lang)` → `{ key, name }`). Doctor services live under the `doctor_home_visit` category, which ships inactive. Providers can only offer services of their own type, so search/booking need no doctor-specific code.
- **Chat (M2.2)** (`services/chat`): one `Conversation` per booking and provider (an admin reassign calls `closeForReassignment`: closed = read-only for the patient, hidden from providers, admins read it via `forAdmin`, audited), `Message` bodies `encryptOnWrite` (decrypted in `ChatService.view`). `chatOpen()` in `chat-window.ts` is the one rule for sending (accepted … 24 h after completed). Live events via `emit/chat.emit.ts`; pushes via `NotificationService.pushOnly` (no in-app record) and never include message text.
- **Card / wallet booking lifecycle**: created in `awaiting_payment` (in `ACTIVE_BOOKING_STATUSES`, so it holds the slot) and invisible to providers — any new provider-facing query must exclude it. The paid webhook moves it to `pending` (SYSTEM, reason `paid`) and publishes `new_request`; the `PAYMENT_EXPIRY` sweep expires unpaid ones. Patient travel-fee charges come from `booking/patient-fees.ts` (`patientFeeFor`) and are stored on `booking.patientFee`.
- **Payments (M2.3)** (`services/payments`): everything provider-specific lives behind `PaymentGateway` (`gateways/`: Paymob, fake). `PaymentService` owns checkout, webhooks (the only source of "paid"), refunds (`refundBooking` reserves the amount atomically) and the unpaid-booking sweep (`PAYMENT_EXPIRY` job). Paid bookings ending without a visit are refunded by `payment-refunds.ts` (a `bookingEvents` listener registered in `runServer`). Tests swap gateways with `setGatewayForTests(new FakeGateway())` and send signed webhooks with `signFakeWebhook`.
- **Payouts (M2.4)** (`services/payouts`): one running balance per provider (`wallet_balances`; + platform owes, − provider owes) moved only through `LedgerService.record` inside a transaction. `PayoutService.generateBatch` takes the whole balance out with a `payout` entry; cancelling adds it back with an `adjustment`. Payout methods and payout destinations are encrypted (`PayoutMethod.accountNumber`, `Payout.destination`); show `destinationLabel` / last 4 everywhere except the admin payout queue. CSV exports go through `csvCell` (formula-injection safe). Payouts store a `statement` (`statementSinceLastPayout`). Cash-commission limit: `CommissionService` (`overLimit` / `overLimitAmong`) — any new path that hands a cash booking to a provider must check it; commission payments are `Payment`s with purpose `commission` (no booking) credited in `creditCommissionPayment`.
- **Packages, promos, referrals, banners (M2.5)** (`services/marketing`): every discount is borne by the platform — `computePrice` puts promo + package coverage + patient credit in `price.discount` (breakdown in `price.discounts`, read via `discountsOf`) and never changes `providerPayout`; on cash completion `recordCompletion` adds a `discount_reimbursement` ledger entry. Benefits are taken in the booking-create transaction (`PackageService.reserve`, `PromoService.redeem` — conditional increments, so limits hold under concurrency — `CreditService.use`) and settled by `settleBenefits()`, which `transitionBooking` calls in the same transaction: completed → package visit used; cancelled / declined / expired / no-show → visit, promo use and credit given back. A booking with total 0 gets payment method `covered` (set by the server, never accepted from the client), `paymentStatus: paid`, and is credited to the provider like a card booking — it never touches cash paths (commission limit, cash collected, commission dues). Gateway-only logic (refunds, collected fees, checkout) checks `GATEWAY_PAYMENT_METHODS`, not "not cash". Patient credit lives on the wallet ledger with owner type `patient` (owner = user id) — provider-facing wallet queries must keep filtering by `ownerType`. Packages: platform only, card / wallet upfront (`Payment` purpose `package`, activated in `activatePackage`, unpaid ones cancelled by the `PAYMENT_EXPIRY` sweep), only providers at or below `perVisitValue` qualify, `PACKAGE_EXPIRY` job (hourly) for expiry + notices. Referrals: `ReferralService` (code on first `GET /me/referral`, linked at sign-up — a phone can be referred once, by HMAC; rewarded on the first completed visit by the `registerMarketingListeners` listener in `runServer`; reward notices are type `account`, so they push even with promotions off — only marketing messages use `promo`). Banners: images under `banners/` via upload purpose `banner`, cached (`BANNERS_CACHE`). Broadcasts (M3.5, `BroadcastService`): `marketing` = `promo` notifications (push respects promotions), `announcement` = type `announcement` (always pushed; super_admin only, reason required — never for offers); daily caps are settings enforced by a unique (type, Cairo day, seq) index; audience = active non-admin users by role + area (patients by address, providers / staff by service area, owners by org area); sent by the `BROADCASTS` maintenance job in 500-user batches with a resumable cursor and a 20 s budget per run; at most once per recipient via `notify({ dedupeKey })` (unique `userId + dedupeKey` on notifications) (the maintenance worker runs one job at a time).
- **Organizations (M3.1)** (`services/organization`): `OrganizationService` (owner side — one org per owner, `getOwn(userId)`; areas / services embedded like a provider's and validated the same way; `teamSizes()` computed from approved staff; `checklist()` + `submit()`), `OrganizationDocumentService` (upload purpose `org_document`), `OrganizationAdminService` (verification decisions + `/admin/organizations`). Organizations share the admin verification routes with providers: `admin-verification.controller.ts` dispatches on `isOrganization(id)`. `commissionRate` on the org overrides the platform rate (to be applied in M3.3 pricing).
- **Staff (M3.2)** (`services/organization/staff.service.ts`): `StaffService` — invites (`org_staff_invites`), joining at sign-up (`joinAtSignup`, inside the registration transaction) or by an independent provider (`accept`: no active bookings, zero balance, no open payout), owner controls (`member()` scopes every lookup to the org → 404 otherwise; services / areas only from the org's lists; `staffSuspended` is an org-level suspension), `remove()` (back to independent, verification kept). Never-accepted invites are hard-deleted 30 days after expiry (`purgeLapsed`, daily job) with only a per-org count kept — the invite SMS must never carry anything about the invitee. Staff profiles have `organizationId` set and must never surface as independents — every provider-facing query for independents filters `organizationId: null`. `RequireActiveAccountMiddleware` refreshes `req.user.role` from the database on each request.
- **Organization bookings (M3.3)** (`services/organization/org-booking.service.ts`, `org-discovery.service.ts`): a booking to an organization has `organizationId`, no `providerProfileId` and `assignmentMode: organization` until the owner assigns (BookingActor `ORGANIZATION`, accepted at once) or a staff member accepts a "send to all" offer. `OrgDiscoveryService.eligibleStaff / freeAt / unionSlots` is the one definition of "a staff member can take it" (approved, not suspended, accepting, area, service, gender, free) — search cards, quotes, assignment, broadcast and fallback all use it. Money for organization bookings goes through `earningsOwnerOf(booking)` (ledger owner type `organization`) — use it, never `providerProfileId`, for anything that credits or debits. Fallback offers can be to an organization (`providerProfileId: null`); booking events `org_request` (owner) and `assigned` (staff) sit beside `new_request`. Owner views must never include booking notes, medical data or visit reports.
- **Organization money (M3.4)**: `PayoutService` takes a provider id or `{ ownerType, ownerId }` (`EarningsOwner`) — payouts, batches, dues, adjustments and statements of payouts work for both. `SubscriptionService` (plans; monthly plan charges kept OFF the earnings balance — settled from available earnings by `settle()` (daily, before payouts) or paid in the app; unpaid → notice / downgrade in `processUnpaid`; never part of the commission limit; `assertCanAddStaff`), `StatementService` (monthly Arabic PDF statements via `statement-pdf.ts` — pdfkit lays Arabic out with the font's `rtla` feature, so every line goes through `rtlLine()` to keep digits / Latin / brackets readable), `OrgReportService` (dashboard, reports), `OrgPackageService` (an organization's packages: booked with that organization, visit priced at `perVisitValue`).
- **Launch prep**: *Test numbers* (`services/auth/test-accounts.ts`): `TEST_PHONE_NUMBERS` + `TEST_OTP_CODE` (validated at boot) — `OtpService` stores the fixed code instead of sending an SMS when `fixedCodeAllowed()`, audits `auth.test_code_issued / used`; sign-up on such a number sets `isTestAccount` on the user (copied to provider profiles and organizations). In production (`setTestAccountIsolationForTests(true)` in tests) the fixed code never opens a non-test account or an admin, and test accounts are kept apart: **any query that picks providers or organizations for a patient must spread `sameWorld(callerIsTest)`** (search, org cards, fallback candidates do), and `QuoteService.prepare` checks `inSameWorld` — bookings carry `isTestAccount`; analytics skip test accounts. *Consent* (`services/consent`): super admins publish versioned texts (`consent_documents`, append-only); `acceptAtSignup` (in the registration transaction) requires the current versions for the role once any exist; `consent_records` are append-only evidence (user, kind, version, action, IP). Interim rule (until counsel answers): `healthDataPaused(userId)` = latest health-data record is a withdrawal → the provider booking detail withholds the medical summary (`medical_summary_withheld`), every medical write (records, documents, `blood_type`) calls `assertHealthDataAllowed` (403 `HEALTH_DATA_CONSENT_WITHDRAWN`), and the profile detail carries `health_data_paused` + notice; data is never deleted. **Any new path that shows a patient's medical data to someone else must check it.** *Account deletion page*: `api/routers/account-deletion/` serves `GET <prefix>/account-deletion` (server-rendered from `account_deletion_page.*` strings; script at `.../app.js`, ES5 in `page-script.ts`, so the default CSP applies) — it only calls the public OTP routes and `DELETE /me`.
- **Clinic visits (C1, in progress)**: `BookingType.CLINIC_VISIT`. Catalog services list `visitTypes` (doctor consultations: home + clinic; nursing: home only) with optional clinic price bounds. Provider / organization service entries carry `visitType` — **missing = home visit**, so match entries only through `services/catalog/visit-types.ts` (`offeredEntry`, `visitTypeMatch`, `visitTypeExpr`, `isVisitType`) and validate lists with `checkServiceEntries`; never match a service entry by `serviceId` alone. Clinics (`services/clinic`, collection `clinics`): text address only, an independent doctor's (or an organization's branch, C4), licence via upload purpose `clinic_licence`, review draft → pending → approved / changes_requested / rejected by verifier admins; an approved clinic whose name or address or licence changes goes back to pending. A doctor's hours per clinic live on `profile.clinics[]` (`slotMinutes`, `instantConfirm`, `hours`); `ClinicService.assertNoOverlap` keeps clinic hours, other clinics' hours and home-visit hours apart (also called from `replaceAvailability`). Settings: `clinic_*`, `max_clinics_per_doctor`, `features.clinic_visits`. Discovery (C2): `ClinicDiscoveryService` (`search` by the clinic's area, one card per doctor and clinic; `slots`; `bookableSeat` = the single eligibility check for a clinic appointment, for C3 quotes; `publicClinics`) — appointments are fixed times via `slotsForDay({ appointmentMinutes })`, and busy time always comes from `DiscoveryService.busyIntervals` (one calendar per doctor). Booking (C3): quote with `clinic_id` (no address) → `ClinicDiscoveryService.bookableSeat` + `clinicTerms`; the booking keeps the clinic address in `address` (so lists / notifications work unchanged) plus `clinicId`, `clinic` snapshot, `visitCode`, `checkIn`. `services/booking/clinic-visit.ts` (`confirmsInstantly`, `confirmClinicVisit` = SYSTEM pending/awaiting_payment → accepted, reason `instant_confirm`, clinic visits only in `canTransition`). `patientFeeFor` uses clinic percentages for clinic visits. `assertClinicBookingAllowed` (run in `prepare`, so at quote, create and reschedule) limits slot hoarding: no overlap per account, one upcoming per doctor and patient profile, `max_upcoming_clinic_bookings` per account. ### Models
- Start schemas from `baseSchemaOptions` (`src/database/schema-options.ts`) and add `schema.plugin(softDeletePlugin)` (spec: soft delete everywhere; see `user.model.ts` for the typing). Queries then skip deleted docs automatically; use `.setOptions({ withDeleted: true })` to include them, `doc.softDelete()` / `doc.restore()` to change them. Unique indexes still see deleted docs — use partial indexes where that matters.
- Sensitive fields (medical data, national ID, license numbers — spec §9) use `encryptedString()` from `src/utils/crypto/field-encryption.ts` and the schema needs `toJSON/toObject: { getters: true }`. `.lean()` returns ciphertext, and encrypted fields can't be queried by value. Models read with `.lean()` everywhere (bookings, disputes) use `encryptOnWrite()` instead: decrypt with `decryptNullable()` in the presenter, and audit the read where it is shown (`auditNotesRead` / `auditDisputeRead`).
- Money is integer piastres (`piastresValidator` in models, `piastres` in zod); times are UTC `Date`s. Shared enums with the frontend live in `src/interfaces/enums.ts`.
- Unique indexes use `uniqueAmongActive` (partial on `deletedAt` null) so soft-deleted records don't block their name.
- Seeds (`src/database/seed/`) run on every boot: `bulkWrite` upserts with `$setOnInsert` only, so admin edits are never overwritten and soft-deleted records aren't re-created. Seed data lives in `seed/data/`.

### Realtime
`src/gateway/index.ts` creates the Socket.IO server and registers one gateway per namespace (`register<Name>Gateway(io)`), with socket JWT auth in `gateway/middleware/`. Code outside gateways gets the instance via `getIO()` from `src/helper/socket.ts`; emitter helpers live in `src/emit/`. Online presence is stored on users and reset at boot, on shutdown, and hourly.

### Queues (`src/queues/`)
- Queue names in the `QueueName` enum (`queue-names.ts`); `getQueue(name)` lazily creates queues with shared retention defaults.
- Job payload types in `jobs/`, enqueue helpers in `producers/`, processors in `workers/`. A new worker must be added to `initQueues()` in `queue-registry.ts`.
- Cron work is done with BullMQ job schedulers (`upsertJobScheduler`, idempotent across instances) defined in `src/utils/scheduled-tasks/index.ts`, processed by the maintenance worker.

### Adding a domain
`src/interfaces/I<Name>.ts` → `src/database/models/<name>/<name>.model.ts` → `src/services/<name>/` (use-cases + barrel) → `src/api/validations/<name>/` → `src/api/controllers/<name>/<name>.controller.ts` → register in `controllerClasses`.

## Conventions
- kebab-case file names everywhere; interfaces named `I<Name>.ts`.
- firebase-admin v14: use the modular imports (`firebase-admin/app`, `firebase-admin/messaging`); the `admin.messaging()` namespace API is gone.
- Firebase credentials come only from the environment: `FIREBASE_SERVICE_ACCOUNT_BASE64` (the JSON, base64; wins) or `FIREBASE_SERVICE_ACCOUNT_PATH` (a file outside git — `secrets/` and `*firebase-adminsdk*.json` are gitignored); Firebase is optional.
